# CI budget implementation plan

Goal: run Linux analysis and regression tests once for ordinary PRs, while retaining complete opt-in and tagged release validation.

Architecture: Builds is the sole automatic caller of reusable Analyze. Full packages require manual dispatch, a current `ci:build` / `ci:full` label on a ready PR, or a version tag. Layout, visual and E2E remain separately available through manual dispatch or their current CI labels (plus `ci:full`). Signing, package integrity and release publication gates stay intact.

1. Remove duplicate Analyze events; gate expensive Builds jobs and add PR label/ready events.
2. Gate layout and harden opt-in events against draft PRs; cancel superseded non-release work.
3. Retain PR diagnostics for 3 days and manual validation for 14 days, preserving tagged release artifact defaults and the existing unsigned archive policy. Add missing Pages timeouts without changing deployment concurrency.
4. Validate all YAML with actionlint, compare release steps and dependency graphs with the base, and exercise event routing for ordinary/draft/labelled/manual/tag scenarios. No cloud dispatch while account Actions is disabled.

Implementation and verification results are recorded in the PR description. This change does not modify application code.

Label removal and conversion to draft cancel obsolete heavy PR work. A remaining opt-in label still applies. Unrelated label events skip in an isolated concurrency group, leaving existing quality/native or full runs intact.
