# 「学习」功能评审

**目标：**评审整个「学习」页签（`morse_core` 引擎、`morse_trainer` 教学逻辑、`morse_io` 键控与音频、应用的训练层与学习界面），在根因处修复真实缺陷。

**方法：**`morse_trainer` 由并行评审完成；其余部分交给 Codex（`gpt-6.1-sol`，只读，基于 `1d15469`）。每个修复都带回归测试。未在真机上运行。

## 已修复

### 教学逻辑（`morse_trainer`）

| 发现 | 影响 | 修复 |
|---|---|---|
| Koch 解锁规则忽略多打的字符 | 分不清两个字符时把两个都打上，得 100% 并解锁下一课 | `KochCourse.passes` 改用 `strictAccuracy`（多打计入错误）；听抄小结显示同一数值 |
| 会话长度可设得低于课程最低值 | 滑块最低 20 字符而一课需要 50；这种会话永远不会解锁，且没有任何提示 | `TrainingSettings.minSessionChars` 取 `KochCourse.defaultMinCharsPerSession`；读取设置文件时把更短的旧值抬到下限 |
| 连续天数用本地午夜之间的 `Duration.inDays` 计算 | 夏令时切换时两午夜相差 23 或 25 小时，连续天数不增加或不归零 | `TrainerProgress.daysBetween` 按日历日期比较；发报会话改走新的 `recordPractice`，两处规则不再分叉 |
| 会话数与字符总数是对已裁剪历史的求和 | 超过 500 次会话后统计页总数不再增长，随后还会减少 | `TrainerProgress` 新增并持久化终身计数；旧文件从历史起算 |
| 间隔复习每次会话都提升所有字符 | 每天的课程练习四天内就把全部已学字符推到 14 天档 | 只有到期的字符答对才升档；答错总是降档 |
| `SrsScheduler.record` 遇到超出区间表的档位会越界 | 结束会话时抛 `RangeError`（只有代码能构造；文件存储已拒收这类文件） | 当前档位先钳到 `maxBox` |
| `CharWeights.explicit` 接受无穷大权重 | 加权抽取永远返回同一个字符 | 拒绝非有限的权重（含默认权重） |
| `recentCharsForLesson` 在第 1 课之后从不计入第一个字符 | 早期课程的额外权重略有偏差 | 窗口按课程计数；到达第 1 课时计入该课的两个字符 |

评审还建议在 `TrainerProgress.fromJson` 里钳位越界数值。没有采纳：`FileTrainerStore` 故意拒收这类文件，以便回退到上一次保存的 `.bak`，钳位会破坏这条恢复路径。

### 键控、音频与训练层

| 发现 | 移动端场景 | 修复 |
|---|---|---|
| 按住键时失去焦点，键一直保持按下 | 桌面以及接硬件键盘的平板：抬键事件发给了新获得焦点的控件 | `StraightKeyButton` 与 `PaddleButtons` 失焦时释放键盘按下的键；手指仍按着的保持按下 |
| 按住键时重开（或切换键控方式）会破坏解码器状态 | 一指按住直键、另一指点「重来」：下一个点被解成 `T` | `MorseDecoder.clearText` 丢弃按住中的码元，新增 `cancelMark` / `SendSession.cancelHeld`；重来、切换方式、进后台时界面释放按住的输入并重建按键控件 |
| 进后台后播放与键控仍在运行，而侧音已静音 | 练习中来电或切换应用：这一轮在听不到的情况下播完 | Android/iOS 进后台时停止听抄播放（回来后点「重播」），并丢弃发报中按住的输入；后台期间不会开始播放 |
| 进度保存失败时练习卡在「记录中」 | 磁盘满：看不到结果，只能返回，而返回时还跳过了离开确认 | 记录方法返回 `saved`；照常显示结果，并弹出提示条，「重试」只重写内存中的进度（不会重复计入会话） |
| 读屏用户无法键控 | VoiceOver / TalkBack 能找到按键，但激活无效 | 直键：按会话速度计时的自定义动作「点」/「划」；双桨：语义点击按下并松开对应桨 |
| 答题键与结果格各占满一整行 | 后期课程的键盘在手机上约 2300 dp 高；结果行竖着堆叠 | 按键按标签收缩（仍 ≥ 48 dp）；每一列结果在发送行与抄收行共用同一宽度，两行一起换行 |
| 与标点同码型的勤务符号被判错 | 完美发出的 `<AR>` 被解成 `+`，发报练习得 0 分 | 目标要求该勤务符号且不要求同码标点时，`SendSession` 把同码标点读作目标勤务符号 |
| 存储的速度只校验为正数 | `characterWpm: 1e300` 能读入，点长四舍五入成 0 | 读取设置文件时钳到滑块范围（速度、Farnsworth、音调、会话长度） |
| 只开触感的配置在桌面上没有任何反馈 | 在桌面上恢复手机的配置 | 当前平台支持的输出都关闭时才回退到闪屏；听抄界面的提示用同一规则 |
| 训练设置里的示例沿用旧开关 | 播放过示例后关掉声音：示例仍有声音 | 改动声音 / 闪屏 / 触感时丢弃示例的播放组件；按旧开关准备好的组件直接丢弃 |
| 每日目标滑块拖动时不动 | 每一步拖动都保存，但界面从不重绘 | 拖动时实时显示，松手时保存一次 |

## 第二轮评审

Codex 复核修复本身，又发现七个问题，均已修复并补测试：

| 发现 | 修复 |
|---|---|
| 手指按住时按键控件被替换，手指稍后的抬起 / 取消在 dispose 之后仍回调（dispose 后 `setState`） | `StraightKeyButton` 与 `PaddleButtons` 卸载后忽略指针回调；dispose 时已释放输入 |
| 把存储的终身计数抬到历史值会掩盖损坏文件，导致完好的 `.bak` 被覆盖 | `fromJson` 保留存储值；`FileTrainerStore` 拒收低于保留历史的计数，从而回退到备份 |
| 示例准备期间切换反馈开关，会出现第二次并发创建 | 同一时间只创建一个；按旧开关建好的组件丢弃后重建 |
| 按需创建的纯闪屏示例播放时看不到闪屏层 | 接受新组件时重建界面 |
| 被取消的按下保留了它之前的间隔，制造出「码元间隔过长」的误诊 | `SendSession.cancelHeld` 移除该间隔 |
| `recentCharsForLesson` 按字符数而非课程数计数，窗口到达第 1 课时漏掉第一个字符 | 窗口为 `count` 节课；到达第 1 课时计入该课的两个字符 |
| 保存重试的界面测试没有真正点到「重试」也能通过 | 测试等待提示条就位、点击「重试」，并检查存储里恰好一次会话 |

## 未修复（及原因）

- **Koch 顺序的表述。** 方案写的是「LCWO 常用序列」，而表是 G4FON 顺序。方案已改为 G4FON；顺序本身不变，学习者的课程不会被重新映射。
- **`MorseTiming` 仍只有 assert 校验。** 它是处处使用的 `const` 值类型；不可信的数值只来自设置文件，而设置文件现在已有边界。
- **进度文件中的课程指纹**（将来 Koch 表变动时用于重新映射课程）留给第一次调整课程表的改动。
- **发报诊断**没有「划过长」类别，且对很短的目标判定严重度；这属于教学细化，不是缺陷。
