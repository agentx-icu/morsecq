# MorseCQ 补充功能改进：实施交接文档

> 日期：2026-10-04。已勘查的应用代码基线：`bae1d5e`。
> 状态：已在分支 `agentx/additional-improvements` 实现（F09–F14）；实现决策、验证情况及尚未在真机验证的内容见 §13。
> 本交接文档以英文版为准；中文版保持相同范围与验收条件。
> 与[现有 F01–F08 规格](./2026-10-03-functional-improvements.zh-CN.md)一起阅读。本补充文档不替代原规格，也不单独构成修改应用代码的授权。

## 1. 目标与优先级

补齐日常通信的可靠性、完整换机迁移和更实用的莫斯训练，保留本地优先、无服务器 Tox 架构及莫斯键控聊天。

已有路线包含每日计划、交互 QSO、聊天练习、节奏回放、体验与水平测试、自定义素材、消息管理和音频工作台；本次不重复建设这些功能。

| 编号 | 补充功能 | 优先级 | 用户结果 |
|---|---|---|---|
| F09 | 连接诊断与恢复 | 高 | 理解通信为何等待，以及可以采取什么行动 |
| F10 | 完整加密备份与换机迁移 | 高 | 将身份和选定个人数据迁移到另一设备，且能核对结果 |
| F11 | 真实电台环境训练 | 中 | 练习干净、均匀音调之外的抄收 |
| F12 | 外接电键与可配置键位 | 中 | 使用已有实体电键/双桨并保留习惯配置 |
| F13 | 中文电码学习与聊天解读 | 中 | 学习四位字符码，并主动解读键发数字消息 |
| F14 | 群组共同训练 | 后续 | 提供可重复使用的教练带练流程 |

若只追加三项，选择 F09、F10、F11。已有每日计划和交互 QSO 继续优先推进。优先级表达产品价值，不意味着一次实现全部功能。

下文默认值均为建议的首版选择。实施前重查代码，重要调整写入本文变更记录。

## 2. 已核实基线与约束

| 区域 | 当前行为 | 本次补充 |
|---|---|---|
| 连接 | offline/connecting/online 三态；持续非在线两分钟显示应用内提示，可重连 | 详细解释、待发送概览和观察到的连接历史 |
| 备份 | MCQB v1 包含身份元数据、Tox 档案和训练目录；仅设置身份密码时加密 Tox 档案 | 原生聊天历史、显式偏好导出、内容选择和整个归档加密 |
| 存储 | 原生历史/队列在身份 data/；学习数据在 training/；部分会话元数据在按身份隔离的键值存储 | 跨多个数据所有者的一致快照 |
| 音频 | 正弦侧音，使用共享音频引擎租约 | 可复现的噪声、衰落、干扰及受限节奏变化 |
| 键盘 | KeyboardKeyBinding 已接受自定义动作集合并提供 swapped()；默认空格/左 Ctrl/右 Ctrl | 配置界面、持久化和实测适配器配置 |
| 中文电码 | ChineseTelegraphCode 与翻译器已支持大陆/台湾码本、前导零及反查候选 | 专项练习和主动聊天解读 |
| 群组 | 已有创建/加入/邀请、消息、成员列表和成员关系恢复 | 带练流程、本地答题和练习小结 |

必须保留：

- 聊天发送只用莫斯键控。答题和诊断不引入文本聊天输入，也不静默发送答案。
- 上线路仍是其他 Tim2Tox 客户端可读的普通文本；cloudCustomData 不是可靠的线路通道，现有群接口也未提供它。
- 只有 morsecq_chat 接触 Tim2Tox/腾讯 SDK；UI 使用 morsecq_chat_api；纯 Dart 包保持分层。
- 训练离线可用；不新增云账号、目录服务、订阅、服务器推送或后台送达承诺。
- 发送方真实节奏传输与同步实时键控依赖上游，首版不包含。
- “我”会话继续仅本地且不可删除；保留旧进度、旧备份和身份隔离。
- 保留触屏/鼠标与键盘键控；必须兼容手机，硬件兼容性按实测平台和设备报告。
- 遵循当前用户评审政策：禁用 Claude 评审，完成适当本地自检与验证。

## 3. F09：连接诊断与恢复

### 3.1 流程与范围

已有连接提示打开诊断页；聊天或“我”中也提供常驻入口，不必等提示出现。

展示本机状态及最近观察到的状态变化时间；最近观察到的成功连接时间或“尚未观察到连接”；选定好友的在线状态，不可用时为“未知”；当前身份/会话的待发送数量和最早待发送时间；可用恢复操作及 P2P/手机后台行为说明。

本机连接和对方在线是不同事实。连接成功时间不是消息送达时间。待发送数量以持久化队列为准，不能只数当前加载的历史页。

重连复用身份/生命周期协调器，展示进行中状态并合并重复点击。重连调用返回不代表网络在线，继续观察事件。保留两分钟提示阈值与不发系统通知的政策，不为日常状态变化频繁提醒。

### 3.2 数据与实现

应用控制器及必要的聊天契约提供类型化快照：身份键、观察时间、本机状态、最近在线时间、可选好友状态、待发送数量/最早时间、操作状态和错误码。

- 不支持的观测值为 null/未知；不根据离线状态推断 NAT、防火墙、对端崩溃、送达或已读。
- 当前 Tim2Tox 轮询无法可靠区分所有失败/已发送状态，不承诺无法提供的失败诊断。重试/取消复用已交付的 F07。
- 身份替换时清空旧观测，旧会话晚到事件不能更新新身份。
- 除显式恢复操作外只读；不丢弃队列，不自动重试状态不确定的消息。
- 技术细节放可展开区域，主页面用日常语言解释。

### 3.3 验收

- 本机在线/对方离线与本机离线/对方未知显示不同解释。
- 队列数量覆盖未加载历史且不重复。
- 重复重连只起一个操作，失败不损坏页面和队列。
- 手机回前台反映最新观测，不声称持续后台在线。
- 新身份不显示旧身份的状态和队列数量。

## 4. F10：完整加密备份与换机迁移

### 4.1 流程与内容

导出：选择内容 → 预览包含/排除项与体积 → 设置备份口令 → 创建一致的加密归档 → 保存/分享 → 显示平台真实结果。

恢复：选文件 → 输口令 → 校验并预览 → 显式确认替换身份 → 暂存并提交 → 恢复报告。分享面板关闭不代表已保存，保留已有各平台 saved/cancelled/failed 语义。

| 类别 | 建议默认值 | 规则 |
|---|---|---|
| 身份与 Tox 档案 | 必需 | 校验身份元数据和档案公钥一致 |
| 训练进度/设置和已保存素材 | 包含 | 包含现有训练文件；F04/F06 细节存在时才纳入 |
| 聊天历史，含“我”会话 | 包含，可选 | 保留消息 ID、顺序和支持的状态 |
| 草稿、置顶、收藏、会话元数据 | 包含，可选 | 盘点实际所有者，不假设 F07 收藏已存在 |
| 可迁移应用偏好 | 包含，可选 | 显式导出键，不复制整个系统偏好存储 |
| 录音等大媒体 | 默认排除，主动选择 | 列明缺失媒体影响和体积，与 F08 对齐 |
| 待发送消息及排队邀请 | 不自动恢复发送 | 报告其存在，执行下述政策 |

窗口坐标、活动音频/按住电键状态、临时诊断、系统权限、令牌、缓存和临时文件不是可迁移设置，不恢复为活动状态。

### 4.2 待发送政策

源设备仍保留队列时迁移身份，可能两边重复发送。首版默认：恢复的待发送记录不自动传输。

用户主动选择包含载荷时，将其恢复为原生活动队列之外的静态草稿/待审条目，显示之前的待发送状态，由用户决定是否重新键发。不承诺恰好一次送达，不将不确定发送包装成确定失败。

排队群邀请也不自动重放，恢复报告说明哪些没有恢复执行。迁移流程提示连接目标设备前停止使用源身份，不新增同时在线账号支持。

### 4.3 格式与恢复要求

- MCQB v1 是长度前缀归档，不是整包加密；保留旧读取器和导入行为。
- 新完整备份使用带版本的认证加密封装；身份元数据、聊天、训练和私有清单一起加密，公开信息仅限解密所需内容。
- 使用维护中的加密库及其口令派生能力，保存有资源边界的派生参数和格式标识，不自造密码算法。[libsodium 文件加密](https://doc.libsodium.org/secret-key_cryptography/secretstream)和[密码哈希文档](https://doc.libsodium.org/password_hashing)仅是参考方案，不代表仓库已有可调用 Dart 接口。
- 选型前核实所有平台绑定；编码前定义版本、认证元数据、资源限制、结束记录校验和错误处理。
- 备份口令与身份解锁密码分开，导出不静默改身份密码。若内部 Tox 档案仍使用另一密码，预览说明额外解锁需求。
- 盘点 data/、training/ 和按身份隔离的键值项；不随意复制目录，不假定所有偏好都在身份目录中。
- 协调 persist/flush、原生历史/队列写入者及偏好所有者，取得一致快照。flush 不阻止复制期间继续写入，应暂停写入或使用经验证的快照机制。
- 替换前校验认证、公钥、版本、允许路径、重复条目、数量、体积及必需数据；不跟随符号链接，不越界解包，未知格式明确失败。
- 复用暂存、替换代次和回滚。文件替换与外部偏好更新需要可恢复事务，单次目录重命名不使两者自动原子。
- 失败保留当前安装，提交成功前保留可恢复旧快照；成功/取消后清理敏感暂存，不能销毁唯一可恢复副本。

### 4.4 验收

- 旧 MCQB v1 样例仍可导入；新备份的原始字节不暴露样例昵称、聊天正文和训练文本。
- 正确口令恢复选定类别和同一身份，报告省略项。
- 错密码、篡改/截断、危险路径、重复条目和超限输入不替换当前账号/偏好。
- 导出中的新消息/训练保存被一致包含或排除，不产生历史/队列错配。
- 恢复待发送载荷和邀请，包括重启后也不自动发出。
- 跨平台保留支持的逻辑数据，不应用无效窗口坐标或源设备硬件绑定。
- 文件/偏好提交间故障可恢复，重复恢复不重复计分或复制历史。

## 5. F11：真实电台环境训练

### 5.1 范围与流程

听抄增加可选“清晰”“轻度干扰”“电台练习”预设，默认清晰。开始前可试听，练习中显示当前条件，作答后允许听干净参考音。

第一步实现可复现背景噪声与信号衰落；第二步加一个邻频音调/干扰莫斯源和受限节奏变化。开放堆叠呼叫、发射机接入和传播预测留后续。

速度独立于环境条件；提高难度不静默改变字符/有效 WPM、不增加播放响度，也不通过未受影响的闪光/触觉暴露答案。

### 5.2 数据、音频与评分

不可变场景保存版本、种子、字符/有效 WPM、音调、噪声、衰落、可选干扰、节奏变化和辅助状态。

- 目标信号与效果分开，原始明文仍为评分依据，解码器输出不是用户答案。
- 使用种子和有界非负时长，相同版本/配置/种子在声明的渲染误差内复现场景。
- 场景生成脱离 Flutter 可测；播放经 morse_io 和现有租约，不替换低延迟发报侧音。
- 混音幅度有界、防削波；暂停、导航、后台、销毁时停止，回前台需用户继续。
- 使用干净参考音或未受影响的视觉/触觉时标为辅助。效果无法感知时解释音频要求，保留普通无障碍练习。
- 与 F01–F08 共用练习记录，保存环境元数据，仅比较同类场景/速度，不混进清晰模式提速建议。
- 首版不自动解锁 Koch；记录活动与独立环境成绩，未定义政策前不混入清晰抄收的 SRS/弱项累计。

### 5.3 验收

- 清晰模式保持现有播放，环境效果由用户开启。
- 固定种子/配置/版本可复现，节奏变化不改符号顺序或产生无效时长。
- 噪声/衰落不改目标文本和名义速度。
- 音频有界，中断后无发声或静音运行的声音实例泄漏。
- 成绩保存条件/辅助，不影响清晰提速、SRS 或课程解锁。
- 手机验证中断、扬声器/耳机切换和回前台。

## 6. F12：外接电键与键位配置

### 6.1 范围与流程

首版通过现有事件路径支持模拟键盘的 USB 适配器。配置页捕获直键/点/划绑定、交换左右桨、选择现有直键/iambic A/B、显示输入与侧音测试，并保存命名配置。

复用 KeyboardKeyBinding 及交换能力，无设备时仍可触屏/鼠标键控。USB MIDI、串口、蓝牙、适配器固件设置及发射机控制另立后续平台工作。

[Vail Adapter](https://github.com/Vail-CW/vail-adapter)提供键盘/MIDI 接口，仅证明接入方向可参考，不代表 MorseCQ 已兼容或兼容其所有模式。

### 6.2 行为与持久化

- 首版是键位预设，通用键盘事件未必能识别具体物理设备，不承诺自动设备检测。
- 三种动作、桨方向和模式保存为带版本的设备本地配置，Learn/Chat/Reference 共用选定配置。
- 拒绝冲突键位，不依赖现有动作优先级兜底；解释系统保留/不可用按键，提供重置。
- 忽略重复按键，支持双桨同时按住；失焦、后台、导航和配置替换时释放动作。
- 适配器自带键控器/侧音时区分已定时直键输入和双桨输入，不对已定时按下/抬起再次生成 iambic 序列，允许关闭应用侧音。
- 丢失 key-up 时不得持续发声。模拟键盘设备断开不一定可观测，保留失焦复位与显式停止/重置，报告剩余平台限制。
- 输入测试不发聊天、不计训练分。
- 导入配置在目标设备审核前保持未启用，仅宣称实测组合兼容。

### 6.3 验收

- 默认等同当前行为，自定义/交换重启保留，所有键控入口一致。
- 重复绑定、repeat、同时按桨、失焦和改配置不导致重复或卡住码元。
- 文档配置中适配器定时码元不被二次键控。
- 无适配器仍可触屏/鼠标/普通键盘练习。
- 至少实测一种模拟键盘适配器，记录平台、设备/固件模式、焦点、侧音选择和实际延迟；假事件不等于硬件验证。

## 7. F13：中文电码学习与聊天解读

### 7.1 范围与流程

两类独立任务：听四位数字组并抄数字；给汉字或数字组、回忆对应电码/汉字。提供精选入门字符，F06 存在后支持自存字符。码本始终可见并随尝试保存，数字抄收与码本记忆分别报告。

聊天选定消息/数字序列后主动“按中文电码解读”，显示原数字、候选汉字、未解码组与大陆/台湾选择。仅本地解读，不自动转换普通数字。

### 7.2 解析、歧义与统计

- 复用 ChineseTelegraphCode、生成表和 charsOf()，不另建映射表。
- 保留四位和前导零，首版解读只接受空白分隔的四位组，其它文本保留，残缺/无效组标明。
- 不直接把宽松 decode() 作为聊天解析器：它抽取数字串、丢其它文字、切四位并选首个候选。聊天要保守解析且显示歧义。
- 多候选全部提供，不静默按 Unicode 码点选第一个，不把等价字形判错。
- 未知组原样可见并标未解决；不覆盖历史正文、不发送翻译消息。
- 外发仍由用户键发数字，查询汉字电码不能变成自动文本聊天发送。
- 数字抄收复用数字评分，四位组不是一个已掌握莫斯符号；辅助尝试注明，仅符合原政策的已学数字更新 SRS。
- 码本记忆建立独立指标，不解锁 Koch、不影响报速建议；保存码本和映射表版本。

### 7.3 验收

- 前导零在播放/作答/保存/解读中完整保留。
- 大陆/台湾差异和多候选可见且正确评分。
- 普通数字默认显示不变，解读需主动操作。
- 混合文本、长数字串、残组、未知码保留或标明，不静默丢弃。
- 查表揭晓标辅助，记忆指标与抄收/Koch 分开。
- 所有界面语言可显示码本名、说明和汉字，不绑定 UI 语言。

## 8. F14：群组共同训练

### 8.1 首版：手动协调、本地评分

群内新增练习入口，本地会话保存标题、教练/参与者角色、来源消息 ID、轮次、播放偏好、作答和小结。

教练用已有莫斯键控输入发送题目，参与者主动选消息，在本地训练页抄收并查看自己的结果。轮流顺序是本地建议清单，教练通过普通群消息宣布轮次。

每人按自己的速度播放；答案、成绩和草稿留本地。分享结果需独立主动操作，且保持莫斯键发规则；首版不自动广播成绩。

这一流程不假设现有群元数据支持同步会话、远端角色强制或认证自动成绩报告。

### 8.2 状态与后续边界

- 保存会话/轮次 ID、来源、尝试、辅助及完成状态，存在时复用 F03 和共用记录。
- 同消息/尝试 ID 不重复计分，重练生成新尝试，小结不再次增加会话。
- 原消息删除标来源不可用，明确保存练习副本才按 F03/F06 规则持有和删除。
- 退出/后台停止声音并释放键，重新打开恢复元数据，不恢复按住、播放或自动发送。
- 离线可练已有本地消息，不承诺每个成员始终收到全部历史和漏过轮次。
- 新会话元数据留本地，恢复不自动重入群、邀请或发布，由现有群行为控制。
- 共享房间 ID、同步轮次、分布式角色、远端成绩收集、计时器需另定协议和能力协商。先查上游消息注解 RFC，不使用未上传的 cloudCustomData，不把任意普通群消息当可信命令。

### 8.3 验收

- 一名教练和两名参与者用普通群消息/本地评分完成手动协调练习。
- 各人速度不同但消息内容一致。
- 提交答案不改聊天草稿、不发群消息。
- 重启保留本地进度，重复提交不重复计分。
- 普通 Tim2Tox 客户端仍能读题，无需支持会话。
- 离线/来源缺失明确，不虚构完成轮次或同步状态。
