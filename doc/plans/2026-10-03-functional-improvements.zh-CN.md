# MorseCQ 功能改进规格与 AI 实施交接文档

> 日期：2026-10-03。代码勘查基线：`bae1d5e`。
> 状态：**已实现（M0–M8），2026-10-03**，分支 `agentx/functional-improvements`；见 §17 实现记录。以下各节仍是规格本身。
> 中文是原稿；英文版应保持同样的范围、默认参数和验收标准。
> 面向接手的实现 AI：按本文的里程碑交付，先核对当前代码，保留已有行为与用户数据。

## 1. 目标与交付范围

把 MorseCQ 的“学莫斯、用莫斯聊天”串成完整流程：开始体验 → 有针对性地练习 → 理解通联流程 → 和真人交流 → 从交流中继续学习。

本规格包含八项功能。顺序是推荐的产品优先级，具体开发依赖见 §13。

| 编号 | 功能 | 优先级 | 用户得到的结果 |
|---|---|---|---|
| F01 | 每日训练计划与速度建议 | 高 | 打开应用就知道今天练什么、为什么练、下一步是什么 |
| F02 | 交互式 QSO 模拟器 | 高 | 独自练习完整的轮流收发、信息交换和请求重发 |
| F03 | 聊天与学习联动 | 高 | 把收到的真人消息变成可评分、可复习的练习 |
| F04 | 发报节奏回放与针对性重练 | 中 | 看见、听见具体哪里敲得不合适，并马上纠正 |
| F05 | 首次体验模式与水平测试 | 中 | 先体验；已有基础者得到合适的课程起点建议 |
| F06 | 自定义练习素材库与音频导出 | 中 | 练习自己关心的文本、呼号与词表，并离线听练 |
| F07 | 聊天消息搜索、收藏、重试与取消待发送 | 中 | 更容易管理历史、重要消息和失败发送 |
| F08 | 音频听抄工作台 | 后续 | 导入录音、选段循环、解码并对照自己的抄收 |

默认实现路线：本地、离线、规则驱动。核心能力不依赖生成式 AI、账号服务器、云同步或订阅服务。

下述阈值是首版产品默认参数，不是已经经过教学研究验证的结论。将参数集中定义，并用实际体验再调整；不能把“推荐”写成能力认证。

## 2. 代码现状与必须保留的能力

### 2.1 已有能力，不要重复建设

- Koch 课程、Farnsworth 间距、十种听抄类型、弱项加权、间隔复习、混淆矩阵、每日字符目标与统计。
- 发报支持屏幕直键、双桨、桌面键盘；已有逐字符对齐、测量报速和文字节奏诊断。
- QSO 目前由模板生成听抄文本，不是根据用户回答推进的交互会话。
- 聊天训练模式目前隐藏收到消息的明文，但仍展示点划；有手动揭晓、播放和自动播放。
- 单聊、群聊、发给自己的本地会话、历史分页、草稿、置顶、离线队列与状态恢复。
- 会话列表已有搜索；F07 补充的是历史消息正文搜索。
- 麦克风实时解码已有音量、音调锁定、调谐与文字显示；没有本规格所述的录音文件工作台。
- 身份备份已经包含训练目录，不能把“训练备份”当作全新功能。
- 十种界面语言、五种风格、明暗模式、手机与桌面的响应式布局。

### 2.2 必须保留的产品约束

1. 聊天发送继续只支持莫斯键控。练习中的抄收答题控件不等于恢复聊天文本输入。
2. 上线路的消息仍为普通文本，兼容其他 Tim2Tox 客户端；新学习元数据只保存在本机。
3. “我”会话不发送到网络、不可删除；现有“清空记录”规则继续有效。
4. 手机与桌面都支持触屏/鼠标键控；有硬件键盘的环境同时保留键盘键控。
5. 练习与素材离线可用。聊天仍受 Tox P2P 连接与移动端后台能力限制。
6. 多账号同时在线、服务器推送、语音/视频、真实键控节奏传输不在本文范围。
7. F05 是明确的产品调整：交付该功能时才将“训练也必须先创建身份”改为“体验可使用独立本地档案”。其他里程碑不能提前放松启动门。

## 3. 共用架构、数据和统计规则

### 3.1 模块分工

```text
Flutter UI → 应用控制器与文件存储
                 ├─ morse_trainer：莫斯分词、计划、评估、QSO 状态机、素材训练、评分
                 ├─ morse_core：字母表、编码、时序与键控解码
                 ├─ morse_io：播放、键控、文件音频输出
                 ├─ morse_dsp：PCM 分块解码、音频时间定位
                 └─ morsecq_chat_api → morsecq_chat → Tim2Tox
```

- 纯 Dart 包不引入 Flutter、平台文件选择器或聊天 SDK。
- 只有 `morsecq_chat` 接触 Tim2Tox/腾讯 SDK。UI 通过契约调用功能，不直接操纵离线队列文件。
- 不为了新功能替换现有 provider、播放租约、身份隔离和持久化屏障。
- 参数、时钟、随机数可注入；计划和模拟器能在固定输入下确定性回放。

### 3.2 统一练习记录

现有 `SessionSummary` 只记录时间、字符数、正确数、课次、类型和耗时，无法可靠比较不同速度，也不足以保存辅助条件。增加兼容旧数据的练习元数据，建议名称为 `ExerciseRecord`：

| 字段 | 要求 |
|---|---|
| `id`、`schemaVersion` | 每次独立尝试具有稳定 ID；保存重试沿用 ID；重新练习产生新 ID |
| `profileKey`、`source` | 本地档案标识；来源为课程、复习、计划、模拟 QSO、聊天、素材、水平测试、发报、录音 |
| `kind`、`startedAt`、`finishedAt` | 训练类型与时间；时间保存为可恢复的时间戳，日目标按用户本地日历计算 |
| `characterWpm`、`effectiveWpm`、`toneHz` | 保存实际使用的字符速度、间距对应的有效速度和音调；未知值为 null，不能填 0 冒充实测 |
| `expectedSymbols`、`correctSymbols`、`insertions` | 复用现有分词和对齐语义；prosign 算一个符号；空格不作为已掌握字符 |
| `strictAccuracy` | 使用现有严格准确率；不能让多打字符提高成绩 |
| `perCharStats`、`confusion` | 保存该次摘要所需的统计，支持近期窗口；不能只使用终身累计值作提速依据 |
| `activeDurationMs` | 排除暂停、后台和等待用户操作之外的空闲；旧会话墙钟耗时不回填为主动练习时间 |
| `completed`、`assistance` | 区分完成、放弃、重播、揭晓、看提示、辅助解码等条件 |
| `planStepId`、`sourceRef` | 可选来源引用；不得在统计里额外复制完整聊天正文或录音 |
| `detailRef` | 可选节奏/音频细节引用；细节缺失不影响已有课程进度的读取 |

这些字段描述契约，不要求全部塞进同一个类。建议扩展现有摘要并按需保存细节，避免建立第二套相互矛盾的总计。

### 3.3 计分与解锁政策

| 来源/条件 | 活动记录与日目标 | 弱项/SRS | Koch 自动解锁 | 速度建议样本 |
|---|---|---|---|---|
| 满足当前课程规则的无辅助课程听抄 | 是 | 是 | 沿用现有规则 | 是 |
| 无辅助复习、专项、支持符号内的素材/聊天抄收 | 是 | 是，仅已学且实际作答的字符 | 否 | 同类、同速且足量时可用 |
| 已揭晓、看提示或重播后的练习 | 是，注明辅助 | 默认不更新；重开独立无辅助尝试后才更新 | 否 | 否 |
| 发报练习 | 是 | 不混入抄收统计；建立独立发报指标 | 否 | 不混入听抄速度建议 |
| QSO 语义交流、水平测试、辅助录音解码 | 独立记录；完成有效作答可计活动目标 | 默认不更新 | 否 | 否 |
| 未作答、仅播放、未完成的空会话 | 可保存草稿 | 否 | 否 | 否 |

这里是新增流程的政策。现有练习是否使用重播、揭晓，需要实现方把辅助状态接入后才能按表判定；不要凭旧历史推测这些状态。

补充规则：聊天包含未学字符时可以继续自由练习，但这些字符不进入已学字符 SRS；解码器输出不是用户抄收答案；重复播放不重复计数；不能在“记录练习”和“完成计划步骤”两处各计一次会话。

### 3.4 持久化与迁移

- 旧 `progress.json`、设置、身份备份继续可读。新增字段有缺省值，并显式处理版本；不伪造旧记录的速度、主动时长或辅助状态。
- 练习记录、一次性计数与计划完成标记必须通过同一个权威进度提交保存，或通过可恢复的提交日志协调，不能假定多文件写入天然原子。
- 重复提交同一个 `id` 不再计数；重启后也成立。裁剪历史时保留未完成提交的去重信息，重练明确生成新 ID。
- 节奏/音频细节先写入成功，再提交引用。删除细节允许摘要保留；孤儿文件可在无在途写入时清理。
- 统一使用现有原子 JSON、串行写入、有效 `.bak` 回退、身份替换代次保护及 `flush`。
- 保存失败仍展示本轮结果与重试入口；重试只保存原结果，不重新评估或重复计分。
- 建议每档案保留最近 500 条详细练习摘要，沿用历史上限；终身总计不能因裁剪下降。额外细节缓存默认 20 MiB，收藏内容显式管理。
- 新数据放进身份训练目录，使现有备份自动纳入。F07 的聊天历史/队列不因此自动包含在身份备份里，不能向用户承诺“全聊天备份”。

## 4. F01：每日训练计划与速度建议

### 4.1 用户流程

学习首页新增“今日计划”：显示预计用时、步骤、每步推荐理由、完成情况和“开始/继续”。保留原有自由练习入口与每日字符目标。

完成一步后显示该步结果和下一步；完成整轮后显示今天的收获、最需要改进的 1–3 个字符，以及明天/下一轮建议。

默认提供 5、10、15 分钟预算。预算是引导，不在字符或按住电键途中强行结束。

### 4.2 计划生成规则

1. 输入：课程位置、已学符号、到期 SRS、近期弱项/混淆、设置、预算、当地日期、已完成步骤。
2. 第一优先处理到期复习；第二处理有足够样本的易混字符；第三安排课程巩固；最后安排短发报练习。
3. 10 分钟计划建议分配：复习 3 分钟、专项 2 分钟、课程 3 分钟、发报 2 分钟。
4. 某类不可用时，把其预算分配给可用类别，不显示空步骤。少于两个适用符号时使用已有可生成练习的回退规则。
5. 新手默认在当前课练习。专项只取已学符号；不会因计划生成而跳课。
6. 计划一旦开始，内容、速度和随机种子冻结；完成步骤不会重新生成整轮。用户主动“重新安排”只改尚未开始的步骤。
7. 当天日期变化生成新计划；昨日未完成计划可查看并作为自由练习继续，不能误计为今天的新计划完成。
8. 课次/速度设置改变时，未开始步骤标为需更新；正在作答步骤保留快照。开始前校验档案仍一致。

课程步骤保留生成时的课次。若前一步已经推进课次，后续仍针对旧课的步骤改为巩固、不再次推进新课；不能把旧题成绩套用到新课解锁。

Koch 课程步骤仍需达到当前最低字符量（目前 50）才能解锁。预算太短时，将该步标为巩固专项、禁止解锁，或延长预计用时并说明；不能创建永远无法达标却标为“课程闯关”的步骤。

### 4.3 首版速度建议算法

- 仅比较最近 14 天内同训练类型、同字符速度、同有效速度的无辅助已完成练习，取最近 5 次。
- 至少 3 次、每次至少 50 个目标符号；样本不够时显示“继续积累”，不建议提速。
- 加权严格准确率达到 95%，且每次至少 90%：建议有效速度增加 1 WPM。
- 最近 3 次均低于 80%：建议有效速度降低 1 WPM或先做专项；不自动修改设置。
- 有效速度不能超过字符速度。达到两者相等后，才建议字符速度与有效速度一起增加 1 WPM。
- 始终遵守当前设置边界（字符 10–40 WPM，有效速度至少 5 WPM）；用户点“采用建议”后才保存。
- 同一批样本只建议一次；同一计划内不同时引入新字符与提速。降低速度也是建议而非失败处罚。
- 发报、QSO 语义分、水平测试和未知辅助状态的旧记录不参加计算。

### 4.4 数据、文件与验收

新增候选：`packages/morse_trainer/lib/src/daily_plan.dart`、`daily_plan_builder.dart`、`speed_recommendation.dart`；`apps/morsecq/lib/training/daily_plan_controller.dart`；`apps/morsecq/lib/ui/learn/plan/`。

修改：`training_controller.dart`、`learn_home.dart`、练习摘要/进度序列化、统计界面；用纯 Dart 生成器，UI 只负责展示和执行。

计划包含 `id/date/profileKey/seed/settingsSnapshot/steps`；每步包含稳定 ID、类型、符号池、预算、解锁资格、状态、结果引用及可本地化的推荐理由代码。

验收：相同输入生成相同计划；全部内容可用现有答题键输入；无到期复习不会生成空练习；重启继续原计划；重复完成不重复计数；跨日/DST正确；三次高分才建议提速，点击采用前设置不变；短预算不破坏解锁规则。

## 5. F02：交互式 QSO 模拟器

### 5.1 首版范围

提供两个场景：“回应 CQ”和“主动呼叫”。先用本地状态机和受控模板，支持呼号、RST、姓名、QTH、请求重发、结束；竞赛堆叠呼叫、开放式长谈和噪声信道留待后续。

默认在当前 `qsoFromLesson` 门槛（目前 30）后开放；未达到时说明前置要求。水平测试可以建议起点，但不能在未选择课程位置时绕过门槛。

### 5.2 会话流程与状态

```text
配置 → 对方 CQ / 等待用户 CQ → 呼号确认 → RST/姓名/QTH交换
     → 信息确认 → 73/<SK>结束 → 小结
每个可收发阶段均可：暂停、听不清请求重发、查看提示、退出。
```

- 用户使用现有直键/双桨及键盘键控发报，解码后显式提交。禁止靠键控暂停长度猜测用户已经决定发出整句。
- 对方响应以完整文本快照生成，并按用户播放参数播放；暂停/进后台时停止，回来由用户继续。
- 对方呼号、姓名、QTH、RST一轮内保持一致；相同 seed 能复现整轮。
- “AGN”或“PSE AGN”请求重发当前对方信息，不重复推进状态；“QRS”令后续播放有效速度降低 1 WPM、遵守下限。
- 同一提交 ID 只处理一次；页面重复点击/重建不产生第二个对方响应。
- 错误回答停留原状态，提示缺少的信息；用户可以重试。连续 3 次错误增加具体提示入口，不自动代答。

### 5.3 语义评估

评估“是否完成这一步的信息交换”，不能要求逐字复制唯一模板。

- 复用莫斯分词、大小写/空白规范化和目标相关 prosign 别名规则；保留标点与勤务符号区别。
- 呼号步骤要求场景配置中的呼号及合理的 `DE` 关系；缺少或错写对方呼号不能判通过。
- 报告步骤接受普通 RST 与规定的缩略数字（如 `5NN`）；只对 RST 槽位转换，不把普通单词里的 N/T 全部改成数字。
- 姓名与 QTH 使用受控词表，允许 `NAME IS`/`NAME`、`QTH IS`/`QTH` 等列明的句式；首版不声称理解任意自然语言。
- 结束接受场景定义的 `73`、`<SK>` 等形式。请求重发和请求减速是独立意图，优先识别。
- 每个场景提供通过/不通过样例和允许变体表，避免实现 AI 自行猜测通联规程。

样例：对方为 `K1ABC`，用户为 `BD1XYZ`，呼号确认阶段可接受 `K1ABC DE BD1XYZ K`；`K1ABD DE BD1XYZ K` 应提示对方呼号错误；`PSE AGN` 应重播并保持本阶段。

首版允许形式以槽位验证为主，额外的礼貌缩语不影响正确字段；不能只检查是否包含某个子串。最低判定表如下：

| 阶段/意图 | 接受形式 | 必须拒绝/区分 |
|---|---|---|
| 主动呼叫 | `CQ`至少一次，`DE {LOCAL}`，允许重复本方呼号，结尾`K` | 缺DE/本方呼号或使用错误本方呼号 |
| 呼号确认 | `{REMOTE} DE {LOCAL}`，结尾`K`或`KN` | 呼号角色颠倒、仅用相似子串命中 |
| 发送报告 | `UR RST {RST}`或`RST {RST}`，允许重复报告 | RST按现有RST工具的范围校验；切数字只在此槽位解释 |
| 姓名/QTH | `NAME [IS] {LOCAL_NAME}`、`QTH [IS] {LOCAL_QTH}` | 必须与本轮配置匹配，不接受对方的姓名/QTH冒充自己 |
| 请求重发 | `AGN`或`PSE AGN`，允许末尾`?` | 重播上一段，不当作字段回答或结束 |
| 请求减速 | `QRS`或`PSE QRS` | 调整速度但不推进信息交换阶段 |
| 结束 | `73`并带`<SK>`，允许呼号、`TU`、`CUL` | 单独`K`不算结束；prosign同码型沿用目标上下文规则 |

小结分开显示流程完成、字段正确、请求重发次数、提示次数和发报节奏。不能把语义得分包装成听抄准确率或用于 Koch 解锁。

### 5.4 数据、文件与验收

新增候选：`packages/morse_trainer/lib/src/qso/{qso_scenario,qso_session,qso_intent,qso_evaluator}.dart`；`apps/morsecq/lib/ui/learn/qso/`。

保留 `qso_drill.dart` 的模板听抄；新增完整的 `QsoSession`，记录 `scenarioId/version/seed/roles/state/turns/assistance`。未完成会话恢复状态与文本，但不恢复按住电键或正在播放。

验收：两个场景完整走通；合理变体通过，错呼号不通过；AGN 不推进、QRS 不越界；双击提交不产生重复回复；所有手机/桌面键控方式可用；无网络也能完成；不增加任何网络消息或改变上线路协议。

## 7. F04：发报节奏回放与针对性重练

### 7.1 用户流程

### 7.2 诊断规则

- 复用 `SendSession.marks/gaps` 的实测值；本机回放保存的是按键时间线，不需要麦克风录音。
- 标准时序由 `MorseTiming` 生成。区分按用户目标速度对比和按其估计点长归一化诊断，UI 明确说明。
- 现有诊断保留，并补充“划过长”；阈值集中定义，依据测试与体验调整，不改成随意硬编码。

- 自己的实录保持原始时长；变速回放若提供，应显式标记倍率，不能覆盖原数据。
- 字符对齐不确定时显示“未能定位到单一字符”，允许整段重练；不能硬把后面所有码元分配给错字符。
- 针对性重练优先取本轮问题字符，至少提供标准示例和 3 次新尝试。只统计真实新尝试，点击播放不计数。

## 10. F07：聊天消息管理

### 10.1 正文搜索与收藏

- 会话内搜索历史正文，支持大小写无关的文本匹配、发送者/日期筛选；结果含时间、上下文和“定位到消息”。不是只搜索当前已加载的50条。
- 搜索结果排序明确：默认最新优先，以时间和消息ID打破并列；分页使用稳定游标，不能仅用时间漏掉同一时刻的多条消息。
- 搜索由 `ChatService` 契约提供，后端分页读取持久化历史；首版可扫描并缓存，不必须引入全文数据库。处理放后台任务或分块，支持取消。
- 收藏是本地用户动作，以档案+会话+消息ID标识。与F06的“保存独立素材”区分：普通收藏引用原消息，清空历史后失效并清理；素材快照独立存在。
- 深跳转加载目标周围记录且保持阅读位置。搜索页面打开本身不标记整个会话已读、不启动自动播放。
- 纯听训练模式下搜索结果也默认隐藏答案，用户主动切换明文后才显示；读屏遵守同一规则。

### 10.2 状态与操作

| 状态 | 可提供的操作 | 行为 |
|---|---|---|
| `pending` | 取消待发送 | 仅对仍在本机队列、尚未交给传输的消息有效 |
| `failed` | 重试 | 重用该消息的稳定本地ID，不创建第二个本地气泡 |
| `sending` | 查看状态 | 不承诺取消已交给传输的内容 |
| `sent` | 搜索/收藏 | 不提供“撤回”，不把本地删除写成对方也删除 |
| `received` | 搜索/收藏/练习 | 不提供发送重试 |
| 新增 `cancelled` | 查看已取消状态 | 保留本地行，重启后不重新进入队列 |

这是建议的契约扩展：`searchMessages(query, cursor, limit)`、`retryMessage(conversationId, messageId)`、`cancelPendingMessage(conversationId, messageId)`。返回值必须表达成功、状态已变化、不可用/失败，不让UI推断队列是否操作成功。

### 10.3 传输一致性与能力调查

- 当前 `ChatService` 没有这些操作。Tim2Tox 有按会话重放待发送消息和持久化队列条目删除能力，但这不等于已经有安全的单消息取消/重试接口。
- 实现前核对 `FfiChatService` 的发送、队列重放、历史行更新、客户端ID语义和 C2C/群两条路径，写一个最小集成验证。
- 取消必须与自动重放共用锁/串行仲裁：还在队列时取消获胜；传输已取走则返回状态已变化。只调用持久化 `removeItem` 或只改气泡都不满足验收。
- 取消落盘失败保留pending并允许重试；重试失败保留failed。状态事件、历史行和队列恢复必须一致。
- 重试仅针对确认为失败的消息；投递结果不明的情况不能声称保证对方只收到一次。本地稳定ID去重不等于网络端到端恰好一次。
- 如安全仲裁需要上游能力，在 Tim2Tox 独立仓库实现并更新子模块pin，不在 `third_party/` 原地修改。搜索、收藏可先交付；取消功能未满足传输验收前不能显示假按钮。
- 单聊、群聊、自己会话按能力处理；自己会话不走队列，不提供无意义的重试/取消。

### 10.4 文件与验收

验收：搜索找到未加载旧消息；同时间戳分页不丢/重复；跳转保留位置；身份隔离；失败消息反复点击只有一个本地行；取消与上线重放竞争结果正确；重启后取消消息不发送；C2C/群分别集成验证；收藏清理与独立素材的删除规则明确。

## 11. F08：音频听抄工作台

### 11.1 首版格式与范围

保留实时麦克风功能，新增“导入录音”。首版支持 RIFF/WAVE PCM16，单声道或双声道，采样率 8、16、44.1、48 kHz；按真实头信息解析而不是按扩展名猜测。

默认上限同时为 50 MiB 和 20 分钟；超出任一上限拒绝并说明。首版不支持MP3/AAC/浮点WAV，不能把WAV入口标为“支持所有音频”；后续可独立扩展编解码适配。

### 11.2 用户流程

1. 导入 → 显示文件名、格式、时长和简化波形。
2. 播放/暂停，选择开始与结束时间，循环选段；手机提供可读的时间输入和拖动手柄，不能只依赖精细拖拽。
3. 选择自动/手动调谐并解码选段，显示音调、估计速度、文本和不能识别的码型。
4. 切换“自己抄收”：默认隐藏自动解码文本，允许导入/填写配套答案，再按已有评分对齐。
5. 保存选段与笔记为本地音频素材；不自动发送录音到聊天或网络。

### 11.3 解码、播放与资源规则

- 复用 `AudioMorseDecoder`，PCM双声道先正确混为单声道，解码器使用真实采样率；按时间分块处理，不一次加载完整录音成多个大数组。
- 波形使用降采样的min/max包络；解码在worker/isolate或受控分块任务执行，主线程保持可操作，取消后停止后续更新。
- 文件头大小、chunk边界、声道/采样率/位深、截断数据和溢出均验证；拒绝不支持格式不会改变已有会话。
- 选段边界可能落在码元中间：标记首尾不完整字符；解码可读取最多1秒上下文，但结果只展示选段内事件并保留边界说明。
- 保存事件时间为相对原音频的sample-clock位置，禁止使用执行解码时的墙钟时间。修改选段/调谐使旧结果失效。
- 不把DSP音调锁定或门限输出包装成统计学置信概率；未知码型保持未知，让用户手动校正。
- 播放与麦克风采集遵守已有音频会话租约。导入音频无需申请麦克风权限；后台停止播放，回来由用户继续。
- 原文件从外部选择后复制到受管理目录，或明确取得平台持续访问权限；不能持久化一个重启后失效的临时URL。
- 录音是用户主动保存的媒体，默认不自动纳入身份备份以免体积失控；备份界面注明仅含元数据并允许显式选择附带音频。没有媒体时显示缺失提示、提供重新关联/删除。

### 11.4 文件与验收

新增候选：`packages/morse_dsp/lib/src/wav_pcm_reader.dart`（纯解析，不调用平台选择器）、`audio_decode_segment.dart`；`apps/morsecq/lib/ui/listen/workbench/`；`apps/morsecq/lib/training/audio_material_store.dart`。

验收：四种采样率、mono/stereo均解码；不同feed分块产出相同文本/时间；已知CW fixture可识别；损坏头/截断/超限明确拒绝；取消立即停止结果更新；时间轴选段不混入其他段；无麦克风权限仍可导入；后台与其他声音不争抢；重启保存选段可恢复；媒体缺失不使整个进度文件损坏。

## 12. 全局交互与质量要求

- 320 dp手机、横屏、平板与桌面可操作；大字号下结果、按钮和时间轴不溢出。触摸目标至少48 dp。
- 所有新文案进入十种语言ARB，使用已有`S`类；不留英文占位。素材正文、呼号和CW规程文本不强制翻译。
- VoiceOver/TalkBack可以操作新增流程；成绩与时间轴错误不能只靠颜色表示。纯听模式不能通过语义树泄露答案。

- 所有长任务显示进度/取消；取消分享、导入或练习不导致卡死或误计分。
- 数据属于当前档案，删除/恢复/切换档案期间暂停写入，迟到任务不得写入新档案。
- 不添加强制排行榜、签到处罚、公开匹配、云端分析或额外账号系统。
